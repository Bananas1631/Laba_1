# АС «Репетитор.Просто»

Платформа для организации peer-to-peer репетиторства: соединяет частных репетиторов и учеников для индивидуальных занятий «один на один», упрощает поиск специалиста, согласование расписания, оплату через эскроу и проведение онлайн-уроков.

Учебный проект СамГТУ, кафедра «Информатика и вычислительная техника», дисциплина «Методология автоматизации технологических процессов разработки ПО».

## Как организована работа

| Элемент GitHub | Что отражает |
|---|---|
| **Milestones (вехи)** | три стадии календарного плана из разд. 5 ТЗ: предпроектная, разработка, тестирование и сдача |
| **Issues с меткой `эпик`** | подсистемы и крупные блоки работ |
| **Sub-issues эпика** | задачи; у каждой — пункт ТЗ, входные/выходные данные и критерии приёмки |
| **Чек-лист в задаче** | подзадачи |
| **Метки `исп: …`** | ответственный участник |
| **Метки области и приоритета** | backend, frontend, интеграция, тестирование, безопасность…; высокий / средний / низкий |
| **GitHub Actions** | автоматический запуск модульных тестов на каждый push и pull request |

Порядок работы над задачей:

1. Взять задачу из бэклога, создать ветку `feature/<номер>-<кратко>`.
2. Написать код и модульные тесты.
3. Открыть pull request со словами `Closes #<номер>`.
4. CI запускает тесты; слияние в `main` — только после успешного прогона.
5. После слияния задача закрывается автоматически.

## Структура репозитория

```
backend/booking/      прототип подсистемы бронирования (блокировка слота)
tests/                модульные тесты (pytest)
docs/                 ТЗ, архитектура, глоссарий
planning/backlog.yml  декомпозиция ТЗ на вехи, эпики, задачи, подзадачи
scripts/              создание меток, вех и задач в GitHub по бэклогу
.github/              шаблоны Issue и PR, workflow CI
```

## Запуск тестов

```bash
pip install -r requirements-dev.txt
pytest -v
```
